# Configuration

The bridge reads `config.yaml` from its working directory (`/data` in the container) at startup. The file is validated with a schema: a missing required field or a value out of range stops the bridge with a clear error. Optional sections fall back to the defaults below.

Start from the example:

```bash
cp config.yaml.example config.yaml
```

## Full example

```yaml
matrix:
  homeserverUrl: https://matrix.beeper.com/_hungryserv/<your-beeper-username>
  domain: beeper.local
  registrationPath: registration.yaml
  port: 29350
  owner: '@<your-beeper-username>:beeper.com'

zalo:
  credsPath: zalo-creds.session.json
  messagesPerMinute: 60
  burst: 30

bridge:
  dbPath: bridge.db
  mediaMaxBytes: 10485760

network:
  name: Zalo
  networkId: zalo
  logoPath: assets/zalo-logo.png

logging:
  level: warn
```

Relative paths resolve against the working directory.

## `matrix` (required)

| Key                | Type    | Description                                                                                                                  |
| ------------------ | ------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `homeserverUrl`    | URL     | Your homeserver's client-server URL. For Beeper: `https://matrix.beeper.com/_hungryserv/<your-beeper-username>`.             |
| `domain`           | string  | The homeserver domain used for ghost users and the bot. For Beeper: `beeper.local`.                                          |
| `registrationPath` | string  | Path to the `registration.yaml` generated by `bbctl register`.                                                               |
| `port`             | integer | Port the appservice listens on (localhost). Must match the port in `registration.yaml`'s `url`, which `bbctl proxy` targets. |
| `owner`            | string  | Your full Matrix ID, for example `@alice:beeper.com`. Only this user can give bot commands and is invited to every portal.   |

## `zalo`

| Key                 | Default                   | Description                                                                                                             |
| ------------------- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `credsPath`         | `zalo-creds.session.json` | Where the Zalo session is saved after QR login. The file is encrypted; the key sits next to it (see below).             |
| `messagesPerMinute` | `60` (max `240`)          | Sustained rate of messages sent to Zalo. Outbound sends wait for a token from a token bucket that refills at this rate. |
| `burst`             | `30` (max `120`)          | Size of the token bucket: how many messages may go out back to back before the rate limit applies.                      |

The rate limiter protects the account: a sudden flood of messages is a typical reason for Zalo to flag an account. If Zalo throttles you, lower both values.

**Credential storage.** The session is stored AES-256-GCM encrypted. The file starts with `ZBENC1`; the 256-bit key is in a sibling file `.<file name>.key` with mode `0600` (for the default, `.zalo-creds.session.json.key`). Keep both files together when you back up or move the bridge. A session saved by an older version in plain JSON is still read.

## `bridge`

| Key             | Default             | Description                                                                                                |
| --------------- | ------------------- | ---------------------------------------------------------------------------------------------------------- |
| `dbPath`        | `bridge.db`         | SQLite database with the portal, ghost and message mappings. See [Database schema](../reference/database). |
| `mediaMaxBytes` | `10485760` (10 MiB) | Size cap for photos, stickers and link-preview images. Videos and files have a fixed cap of 100 MB.        |

## `network`

How Beeper names and brands the network.

| Key         | Default                | Description                                                                     |
| ----------- | ---------------------- | ------------------------------------------------------------------------------- |
| `name`      | `Zalo`                 | Network display name shown in Beeper (bot profile and each room's bridge info). |
| `networkId` | `zalo`                 | Protocol id written into the rooms' `m.bridge` state.                           |
| `logoPath`  | `assets/zalo-logo.png` | Logo uploaded once per start and used as the bot avatar and the network icon.   |

The top-level network label in Beeper's account list stays the bbctl registration name (for example `sh-zalo`); a custom appservice cannot rename it.

## `logging`

| Key     | Default | Description                                                                                                                                                        |
| ------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `level` | `warn`  | Log level of matrix-appservice-bridge (the Matrix side): `debug`, `info`, `warn` or `error`. `info` also logs every HTTP request, including the 30 s health check. |

The bridge's own lines (`[zalo]`, `[bridge]`, `[sync]`, …) are always logged. See [Logs](../reference/logs).

## Environment variables

| Variable              | Used by              | Description                                                                                                                          |
| --------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `MATRIX_ACCESS_TOKEN` | container            | Beeper access token for `bbctl proxy`, as an alternative to mounting `bbctl-config.json`. Used only when no bbctl config exists yet. |
| `ZALO_WS_TRACE`       | bridge               | `1` logs the header of every Zalo websocket frame (command and size only, never content). For diagnosing unknown protocol frames.    |
| `TZ`                  | container            | Time zone of the container. `compose.yaml` defaults to `Asia/Ho_Chi_Minh`.                                                           |
| `BBCTL_CONFIG`        | container            | Where `bbctl` keeps its login inside the container. Preset to `/data/bbctl/config.json`.                                             |
| `ZALO_CDP_URL`        | history-import tools | DevTools endpoint of Zalo PC. Defaults to `http://127.0.0.1:9229`.                                                                   |
| `ZALO_APP`            | `import.sh`          | Path to `Zalo.app` on macOS when it is not in `/Applications`.                                                                       |

## Files the bridge creates

| File                                | Contents                                     | Secret? |
| ----------------------------------- | -------------------------------------------- | ------- |
| `bridge.db` (+ `-wal`, `-shm`)      | Portal, ghost, message and reaction mappings | Private |
| `zalo-creds.session.json`           | Encrypted Zalo session                       | Yes     |
| `.zalo-creds.session.json.key`      | Key for the session file                     | Yes     |
| `registration.yaml` (you create it) | Appservice tokens                            | Yes     |

All of them are gitignored. Never commit them or paste them into issues.
